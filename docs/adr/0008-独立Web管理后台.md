# 0008-独立Web管理后台

## 状态：已接受

## 背景

曾决议 Phase 1 不做独立管理后台、仅在 App 内隐藏入口运维。多用户上线后，全局目录锁定编辑、用户角色、内容审核与编辑发帖需要可持续的操作面；塞进 C 端 App 会污染产品并难做复杂表格/审核流。

## 决策

1. Phase 1 即建设**独立 Web Admin Console（完整 CMS）**：全局目录、用户与角色、内容审核、品牌上新/官方资讯/风格百科发帖等。
2. Admin 与用户 App **分离**，共用同一 NestJS + PostgreSQL 后端；Admin 前端为 **Vite + React + TypeScript** SPA，UI 使用 **Ant Design**。
3. 废弃「仅 App 隐藏入口作为主管理路径」；品牌官方账号仍更后期。

## 理由

- 目录治理与审核是工具转多用户的刚需，Web 表格/筛选远比移动端隐藏页合适
- 完整 CMS 一次到位，避免先做半套再推翻
- 与「只做 App 给 C 端用户」不冲突：Admin 不是第二个 C 端

## 后果

- Phase 1 后端需提前具备 Post/内容与角色权限模型，即使用户 App 首页信息流仍可占位到 Phase 2
- 工程上至少三个表面：单仓目录 `mobile/`、`admin/`（Vite+React+Ant Design）、`server/`（Nest API）；共用类型可后抽，不强制一上来 monorepo workspace
- 范围与工期明显大于「无管理后台」方案，需优先排期后端 + Admin，而不是先堆 Phase 2 社区 UI
