# 0002-全局物品目录与用户衣橱条目分离

## 状态：已接受

## 背景

Petticoat 中，多个用户可能拥有同一条 Lolita 裙子（同一品牌、同一裙名、同一变体）。如果每个用户独立创建自己的物品记录，会导致数据重复、命名不一致，且无法实现"同款连接"和"想要同款"等核心社交功能。

## 决策

采用**全局物品目录 + 用户衣橱条目（WardrobeEntry）分离**的数据模型：

- **全局层**：Brand → Item → Variant，所有用户共享的公共数据
- **用户层**：WardrobeEntry，记录用户与变体的关系（状态、隐私、预订记录等）

用户录入物品时，先搜索全局目录，找到则关联已有变体；未找到则新建，自动进入全局目录。管理员可事后编辑、合并、删除。

## 理由

1. **同款连接**：多用户指向同一变体，天然支持"谁和我有同款"
2. **想要同款**：用户点 Want 时可精确指向目标变体，而非模糊文本
3. **录入体验**：搜索选择比每次手填快，且数据规范
4. **Lolita 领域特性**：品牌+裙名的组合具有唯一标识性，比普通服装更适合全局目录

## 后果

- 需要实现模糊搜索和去重提示，降低重复创建率
- 管理员需要事后治理工具（合并重复条目、编辑错误信息）
- 全局物品的编辑权限需要审慎设计——修改全局物品会影响所有关联用户
- 物品删除需要处理级联影响（如有用户仍在关联）
