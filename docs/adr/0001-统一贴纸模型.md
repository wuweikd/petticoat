# 0001-统一帖子模型

## 状态：已接受

## 背景

icyProfile 有两大内容产出方向：社区社交（用户 UGC）和内容资讯（官方/编辑产出）。一个自然的选择是为它们分别建立独立的数据模型和页面体系——"社区帖子"和"资讯文章"各自独立。

## 决策

采用**统一帖子（Post）模型**，社区内容和资讯内容共用同一个实体，通过标签和分类字段区分类型。

## 理由

1. **用户体验连贯**：用户不需要在"社区"和"资讯"两个入口之间切换，内容自然流转
2. **数据模型简洁**：一套 CRUD、一套搜索、一套推荐逻辑，而非两套并行系统
3. **内容自然融合**：官方资讯可以出现在社区信息流中，用户的穿搭教程也可以被打上"百科"标签，边界本来就是模糊的
4. **开发效率**：避免维护两套几乎相同的内容管道

## 后果

- 需要在帖子模型上设计足够灵活的分类/标签体系，否则后期区分逻辑会变得混乱
- 权限控制更复杂：官方资讯需要编辑权限，UGC 只需要用户权限，但它们是同一张表
- 搜索和推荐算法需要考虑帖子类型权重
