# 0004-全局目录编辑与删除治理

## 状态：已接受

## 背景

全局 **Brand → Item → Variant** 由用户创建并共享。若任何人随时可改可删，会破坏他人衣橱与同款连接；若创建后完全不可改，冷启动时笔误难以自修。图片反哺目录也涉及同意与版权边界。

## 决策

1. **编辑锁定**：创建者仅在该变体只被自己的 **WardrobeEntry** 关联时可改全局字段；一旦另有用户挂上同一变体，对创建者锁定，仅管理员/编辑可改。用户申请修正时展示同款人数，提醒管理员处理。
2. **删除**：存在任一衣橱关联时禁止删除变体；无人关联才可删。合并/别名重定向留待增长阶段。
3. **目录图**：用户图与目录图分层；用户上传须显式同意「同时用作目录图」，且仅当该变体尚无目录图时才可写入；管理员可事后替换。

## 理由

- 单人可改保证冷启动可纠错；多人锁定保护同款连接的稳定性
- 禁删优于断链；重复条目用改名/改归属顶住，合并工具后置
- 显式同意反哺避免未经许可把实拍铺进公共目录

## 后果

- 需要可靠的「关联用户数」计数（至少区分创建者自己 vs 其他用户）
- 管理员修正队列/入口要尽早有最小形态，否则锁定后错误会堆积
- 目录在早期可能缺图（不同意反哺时）
