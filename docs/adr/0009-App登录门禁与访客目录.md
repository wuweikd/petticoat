# 0009-App登录门禁与访客目录

## 状态：已接受

## 背景

App 从本地 AsyncStorage 迁到 Nest 云端后，需决定未登录能做什么、登录如何打断恢复、以及本机旧数据如何处理。若启动即硬门禁，全局目录无法冷浏览；若未登录仍写本地衣橱，会与「云端为准」冲突并产生两套状态。

## 决策

1. **实现顺序**：先完成 App↔Nest（手机号登录 + 目录/衣橱上云），再做社区信息流/Want 竖切。
2. **本机数据**：登录成功后以云端为准，**丢弃**本机衣橱 AsyncStorage；不自动导入、不询问合并。
3. **验证码**：第一刀开发桩；发码/验码接口形状预留，真短信后接。
4. **访客可读**：未登录可搜索/浏览**全局目录**；不可新建全局 Brand/Item/Variant；不可写入衣橱/预订/个人日历。
5. **个人 Tab**：衣橱/日历/我的可进入，展示空状态 + 登录 CTA。
6. **登录打断**：从「加入衣橱 / 新建目录」等写入动作跳登录；成功后回到拦截前界面，**保留表单/选中草稿**，不自动提交入库。

## 理由

- 云端单一真相，避免游客半本地与登录后双写
- 目录只读开放降低录入前摩擦；全局写入必须有 `createdByUserId` 责任人
- 恢复草稿保留意图，自动提交易产生缺字段半成品

## 后果

- 需提供**无需登录**的目录搜索 API，与需登录的衣橱/新建目录 API 分离
- 客户端要有登录会话与「待恢复草稿」暂存；登录时显式清本地衣橱缓存
- 社区竖切依赖本 ADR 的账号与云端衣橱就绪
