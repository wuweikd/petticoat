# 0007-搭配 Coordinate 模型

## 状态：已接受

## 背景

Phase 2 要做搭配与穿搭分享。若位置挂 WardrobeEntry、或允许直接拼公共目录、或把换装人偶当上线门槛，会分别导致分享语义不稳、衣橱边界糊掉、或社区竖切被表现层拖死。

## 决策

1. **位置主键为 VariantId**：不存 WardrobeEntryId；「未到手」等由作者当前 WardrobeEntry 状态派生；写入时校验该 Variant 已在作者衣橱。
2. **入选范围**：仅自己衣橱（想要 / 预订中 / 已拥有）；不可直接拖未入库目录变体。
3. **主坑 + 额外槽**：主坑与六大 ItemCategory 一一对应（每坑至多一件、可空、品类必须匹配）；额外槽仅允许配件与底层。
4. **与 Post**：可强绑 0..1 套 Coordinate，也可弱挂 Variant 列表；分享必须进发帖编辑器预填后确认，禁止一键静默发帖。
5. **人偶后补**：Phase 2 先上主坑列表编辑器；换装人偶拖拽不作为搭配上线门槛。

## 理由

- VariantId 与穿搭帖弱挂、同款 Want 一致，避免删改衣橱条目捅穿已分享搭配的身份
- 衣橱校验保住「我的方案」，拒绝公共目录拼盘
- 主坑对齐已有品类字典，额外槽只服务可叠穿小物，避免一套多裙购物车
- 人偶是表现层成本，不挡「搭配 → 帖 → Want」闭环

## 后果

- 作者删除衣橱条目后，搭配位置仍指向 Variant，但校验/展示须提示「已不在衣橱」并引导移除或加回
- 访客看穿搭帖上的「未到手」以作者侧状态为准，不是访客自己的衣橱状态
- 弱穿搭帖与 Coordinate 强绑帖并存，信息流与 Want 都按 Variant 工作，不能假设每帖必有 Coordinate
